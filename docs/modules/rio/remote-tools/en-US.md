An organization owner or AI admin can open [Tools settings](/settings/ai?tab=tools) and choose {{ui:remote.add}}.  Enter the server’s name and address, then choose no authentication, an API key header, or OAuth 2.1.  Credentials stay in the credential store.  OAuth uses dynamic registration when offered.  Otherwise, enter a registered client ID and, when needed, its secret.  Choose {{ui:settings.draft.save}} in the page’s save bar before choosing {{ui:remote.authorize}}.  An OAuth server’s tools are listed only after it is authorized, and only authorization registers a client.

Server addresses require HTTPS, except local development connections without credentials.  OAuth endpoints and requests carrying credentials always require HTTPS.  Private network addresses are blocked unless the operator permits them.  When permitted, {{ui:remote.private}} enables them for this connection, including its authorization endpoints.  If the operator stops permitting them later, requests to private addresses are refused, but admins can still edit the connection and turn the switch off.  Every connection checks resolved addresses and pins the request to an approved address.  Redirects are refused.  Streamable HTTP is tried first, with SSE for servers that reject that transport as unavailable.

Choose the refresh icon beside a server to discover tools, then turn on only the tools you need.  New tools start off.  Tools with unsafe regular expressions, external or recursive references, or excessive nesting are skipped with a notice.  Bounded local definitions are supported, and format annotations are ignored.  Discovery keeps at most 100 tools per server.  Changed tool definitions turn off until an admin reviews them.  Catalogs refresh every 15 minutes and on demand.  {{ui:remote.audience}} can include everyone, groups, org units and their children, or roles.  Guests need the explicit guest role, even when they belong to an included group.  Access is checked again when a tool runs.  Each server’s settings have a link you can save or share with another admin.

Every call shows its server, name, and arguments in Rio’s panel.  Tools the server claims only read run directly by default.  Other tools wait for {{ui:remote.approve}} or {{ui:remote.deny}} every time.  An admin can choose {{ui:remote.alwaysAsk}} for an individual tool or require approval for all read-only tools.  Rio asks first when web search results or another connected tool’s results have already entered the same turn.  Approvals expire after 10 minutes.  A changed connection invalidates pending approvals.  An outside change cannot be undone in Riosoma, and a failed call is never automatically repeated.

Labeled library content cannot be sent to outside tools.  After a conversation reads library content or guidance, connected calls are refused for that conversation, including on later turns.  Library names alone do not block calls.  Memories saved from a blocked conversation retain that restriction when recalled in another conversation.  Database classification rules also apply before data leaves through a connected call.  In organizations that already had knowledge libraries, conversations and memories created before connected tools were installed are treated as labeled because their provenance is unknown.  Use a fresh conversation without those memories for connected calls.  Rewriting a memory yourself, outside a conversation, clears its restriction.  The organization’s internal-data rule must allow outside use, and the person’s AI permissions still apply.  When these rules leave connected tools out of a turn, Rio’s panel says so and suggests a fresh conversation without labeled data.

Tool results and descriptions are untrusted data.  Results are limited before Rio reads them.  Calls time out after 15 seconds.  Calls to one server run side by side.  When an OAuth access token expires, one call refreshes it and the others use the new token, so a rotating refresh token is spent only once.  Stopping Rio during a refresh still saves the new token.  Three transport failures, timeouts, or server errors pause a server for 30 seconds.  Caller mistakes do not pause it.  Stopping Rio cancels an active call.  Calls are limited to 20 per person and 120 per server each minute.  Each turn includes at most 32 connected tools within an 8 KB budget, with a notice when tools are left out.  Audit entries identify the server, tool, person, and outcome, without argument values.  Connection changes support {{ui:remote.undo}}, which restores settings with tools off for review.  Finished and expired call details are removed after one day, and undo history after 30 days.  Removing a server clears its credentials from undo history.  Connections survive the departure of the admin who saved them.  Scheduled refreshes and retention cleanup act for no person, so their audit entries name only the organization, and a scheduled refresh is recorded only when a server’s tools or status change.  Connections, credentials, pending approvals, results, and undo history stay out of organization archives.

Connected tool catalogs are also available through the REST API at `/api/v1/remote-tools` and the MCP tool `list_connected_tools`, using the same audience checks.  Session clients can request a tool through `/api/rio/conversations/:conversationId/remote-tools`.  A pending call returns a link to its approval in Rio’s panel.

Long server names truncate beside their refresh control.  Hover the name to read its full text, or focus the refresh control to read the full action in its tooltip.
