# Shared sorting

`SortableList` and `SortableTree` in `packages/ui` preview a destination without moving neighboring controls.  They call `onMove` once on drop or an immediate move.  Callers send that change through their existing command or draft flow.

Use stable item IDs.  Filter groups have optional persisted IDs, saved when legacy filters are next edited.  Legacy IDs start from their original paths so peers agree before the first save, and new groups receive generated IDs.  Once assigned, an ID follows its group through moves and content changes.  Moving a filter prunes ancestors emptied by that move, while the general tree helpers preserve empty containers.

Filter identification also repairs later duplicate group and condition IDs deterministically, including condition IDs that collide with a group's drag ID.  These repairs save with the next edit, without changing condition values or adding a migration.

`orientation` accepts `vertical`, `horizontal`, or `grid`.  Grid order follows rows from left to right, and `columns` declares the number of columns for vertical keyboard steps.  Supply the current column count when a responsive layout changes.  Horizontal lists use Left and Right, vertical lists use Up and Down, and grids use all four arrows.  Vertical trees use Left and Right to leave and enter groups, while horizontal trees use Up and Down.  Set `keyMap` to override a `KeyboardEvent.code`, or use `null` to disable it.  Provide localized `instructions` when customizing keys.

`SortableItem` renders a grip and keeps row controls independent.  Use `keyboardActivator="item"` for item-focused keyboard interaction, and `altMoveScope="row"` for immediate shortcuts from other row controls.  Inputs, text areas, editable content, text boxes, and comboboxes retain their editing keys.  `as` selects a semantic wrapper such as `li` or `tr`.  `renderWrapper(props, children)` lets a composite component own the wrapper, provided it forwards the ref, keyboard handler, accessibility attributes, and data attributes to its element.

In item mode, the grip supports pointer dragging and stays out of the tab order and accessibility tree.  A disabled item's focusable wrapper describes the reason instead of pickup instructions and exposes the reason as its title.  A small wrapper and grip observe drag context changes, while memoized row content stays outside that context.  End zones reserve their label's space even when idle, including horizontal and grid layouts.

`renderOverlay(node)` supplies an optional preview.  `canDrop(id, location)` applies surface-specific rules alongside depth, capacity, and disabled-item rules.  `useSortableMoves()` exposes `item`, `target`, `canMove`, and `move` for menus.  Its moves announce the result and restore focus to the moved control after rendering.

Keep the complete logical item list in `items` when virtualizing.  Keyboard destinations come from that list and the grid column count, without requiring mounted neighbors.  `onRevealItem(id)` asks the virtualizer to mount or scroll to a destination.  It can return a promise that resolves after mounting, so focus restoration can wait for the moved item.  Pointer dragging targets mounted droppables, and scrolling reveals additional targets.

Mouse and pen activate after a short movement.  Touch activates after a brief hold.  Only the grip disables browser panning, leaving the rest of each row available for scrolling.  Escape cancels before a surrounding dialog can dismiss.  A keyboard drag also cancels when focus leaves its activator or a pointer presses another control.

Pointer drops accept gaps within 24 pixels of a visible droppable rectangle, bounded by each ancestor that clips its contents.  Scrolled-out rows cannot catch a release, and the gap tolerance never extends outside a scrolling panel.  Releasing outside the panel cancels, including at a phone's screen edge.  Keyboard sensors read current props throughout a drag.  Pending destinations retain a parent and the next item's ID, resolving their index against current items at commit.  Peer edits update the announced position, and removing the destination item or parent cancels that pending drop.

`dropReason(id, location)` returns a localized refusal before release and for immediate moves.  Its status region remains mounted so changes are announced reliably.  Immediate refusals clear on blur or the next key press.  Asynchronous preflight may return no reason while pending, with the command enforcing the final permissions.  Completed preflight checks resolve and revalidate the anchored destination, even when the pointer stays still.  Never represent pending work as a refusal.  `anchorDisabledItems` defaults to true to preserve disabled rows' positions.  Set it to false when disabled containers may receive items and siblings have no stored order.

`SortableTarget` exposes an external folder or Trash destination through `parentId`.  A pointer must be inside its visible bounds.  It accepts native `onDragOver` and `onDrop` handlers for sources such as desktop files or shortcut links.  Declare external destination nodes in the tree's `targets` prop.  They participate in destination validation without becoming invisible keyboard siblings.  The `items` prop must match the current filtered list, and selections belong to that navigation state.

`useLayoutDrag` shares pointer movement, Escape cancellation, keyboard movement, resizing, and announcements for spatial designers.  Supply the grid ref, column count, row height, layout functions, and one commit callback.  It previews only the active item.  A single computed grid track selects stacked layout behavior regardless of pixel width, preserving horizontal coordinates and disabling resizing and horizontal nudges.
